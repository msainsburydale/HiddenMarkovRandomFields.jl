HiddenMarkovRandomFields.simulatehiddenpotts Function
julia
simulatehiddenpotts(nrow::Integer, ncol::Integer, β, distributions; nchains = 1, num_iterations = 1000, sw_every = 1, save_at = num_iterations, rng = Random.default_rng(), ntasks = Threads.nthreads(), backend = nothing)
simulatehiddenpotts(Z₁::AbstractMatrix, β, distributions; nchains = 1, num_iterations = 50, sw_every = 1, save_at = num_iterations, rng = Random.default_rng(), ntasks = Threads.nthreads(), backend = nothing)

MCMC sampling from a spatial hidden Potts model with inverse-temperature parameter β ≥ 0 and emission distributions (one per label, so that the number of labels is q = length(distributions)), either unconditionally on an nrow×ncol grid (first method) or conditionally on the observed values of the incomplete data Z₁, in which missing marks the values to simulate (second method).

Runs nchains independent chains (in parallel over threads) for num_iterations iterations each, where an iteration is a chequerboard heat-bath Gibbs sweep preceded, every sw_every iterations, by a Swendsen–Wang sweep (sw_every = 0: Gibbs only). Observed values equal to the atom of a Dirac emission distribution are assigned to that label and held fixed.

Returns a named tuple (Y, Z) of labels (integers in 1:q) and data, each an array of dimension nrow×ncol×length(save_at)×nchains containing the states after the iterations in save_at (by default, the final iteration only; iteration 0 is the initial state). In the conditional case, the observed entries of Z equal those of Z₁.

Each chain can have its own parameters, e.g. to simulate a batch of training data with one call: β can be a vector with one value per chain, and distributions a vector with one vector of emission distributions per chain (each of the same length q). nchains then defaults to the number of chains given, and chain c uses β[c] and distributions[c]. In conditional simulation, the Dirac emission distributions must be the same in every chain, since they fix the observed values equal to their atoms; on a GPU, emission distributions per chain are supported in unconditional simulation only.

Up to ntasks tasks run in parallel (set ntasks = 1 when calling from code that is already parallel). The chains are distributed over min(ntasks, nchains) tasks; when there are fewer chains than tasks, the remaining tasks parallelise the sweeps of each chain, for grids of roughly 64 × 64 pixels or more. Results are reproducible given rng, from which the chains are seeded, and do not depend on ntasks or on the number of threads.

To run the chains on a GPU, set backend to a KernelAbstractions backend, such as CUDABackend() after using CUDA. All nchains chains then run as one batch on the device, and Y and Z are arrays on the device (copy them to the CPU with Array). The chains are still initialised on the CPU, over ntasks tasks. The results are reproducible given rng, but differ from those of the CPU sampler. See GPU sampling.

Examples

julia
using HiddenMarkovRandomFields, Distributions

# Inverse temperature and emission distributions (q = 2 labels)
β = 0.8
distributions = [Normal(0, 1), Normal(2, 1)]

# Unconditional simulation
Y, Z = simulatehiddenpotts(100, 100, β, distributions)
z = Z[:, :, 1, 1]

# Conditional simulation, with 30 independent chains
Z₁ = Matrix{Union{Missing, Float64}}(z)
Z₁[rand(size(z)...) .< 0.2] .= missing
Y_imputed, Z_imputed = simulatehiddenpotts(Z₁, β, distributions; nchains = 30)

# Store the chains after selected iterations
Y_trace, Z_trace = simulatehiddenpotts(Z₁, β, distributions; num_iterations = 100, save_at = [1, 10, 50, 100])

# 500 fields, each with its own β and emission standard deviation (e.g., training data)
βs = rand(500)
σs = rand(500)
Y_train, Z_train = simulatehiddenpotts(64, 64, βs, [[Normal(0, σ), Normal(2, σ)] for σ in σs])

# 1000 chains on an NVIDIA GPU: Y and Z are CuArrays
using CUDA
Y_gpu, Z_gpu = simulatehiddenpotts(Z₁, β, distributions; nchains = 1000, backend = CUDABackend())

HiddenMarkovRandomFields.simulatepotts Function
julia
simulatepotts(nrow::Integer, ncol::Integer, q::Integer, β; nchains = 1, num_iterations = 1000, sw_every = 1, save_at = num_iterations, rng = Random.default_rng(), ntasks = Threads.nthreads(), backend = nothing)
simulatepotts(Y₁::AbstractMatrix, q::Integer, β; nchains = 1, num_iterations = 50, sw_every = 1, save_at = num_iterations, rng = Random.default_rng(), ntasks = Threads.nthreads(), backend = nothing)

MCMC sampling from a spatial q-state Potts model with inverse-temperature parameter β ≥ 0, either unconditionally on an nrow×ncol grid (first method) or conditionally on the observed labels of Y₁, in which missing marks the labels to simulate (second method). Labels are integers in 1:q.

The sampler, keyword arguments (including backend, for a GPU) and output layout are those of simulatehiddenpotts: returns an array of labels of dimension nrow×ncol×length(save_at)×nchains. In the conditional case, the observed labels are held fixed. As there, β can be a vector with one value per chain.

Examples

julia
using HiddenMarkovRandomFields

# Unconditional simulation
β = 0.8
Y = simulatepotts(100, 100, 3, β)[:, :, 1, 1]

# Conditional simulation, with 10 independent chains
Y₁ = Matrix{Union{Missing, Int}}(Y)
Y₁[rand(size(Y)...) .< 0.1] .= missing
Y_imputed = simulatepotts(Y₁, 3, β; nchains = 10)

# One field for each of several values of β
Y_β = simulatepotts(100, 100, 3, [0.5, 1.0, 1.5])

Persistent-chain interface ​

These types and functions are public but not exported. Access them with qualified names (e.g., HiddenMarkovRandomFields.run!), or import them explicitly with using HiddenMarkovRandomFields: PottsLattice, PottsParams, PottsChain, run!. They support algorithms that need the same chains across many calls, for example to continue them under new parameter values in a Monte Carlo EM algorithm (Wei and Tanner, 1990), such as the neural EM algorithm (Sainsbury-Dale et al., 2025). See Persistent chains for an example.

Each task keeps its own scratch memory, so separate chains can be updated in parallel. Each chain must be updated by only one task at a time.

HiddenMarkovRandomFields.PottsLattice Type
julia
PottsLattice(Z::AbstractMatrix, distributions; nblocks)
PottsLattice(nrow::Integer, ncol::Integer; nblocks)
PottsLattice(ismiss::AbstractMatrix{Bool}, fixedlabel::AbstractMatrix{<:Integer}, z::AbstractMatrix; nblocks)

Geometry and data layout for MCMC on an nrow×ncol grid, computed once per data set. Each pixel is

  • missing (updated, no likelihood contribution);

  • observed (updated, with likelihood contribution given by column o+1 of the weight table of PottsParams); or

  • fixed (never updated: an observed value equal to the atom of a Dirac emission distribution, or a known label).

The first method is for the hidden Potts model with data Z (missing marks missing values), the second for unconditional simulation (every pixel missing), and the third gives full control: ismiss marks the missing pixels, fixedlabel the fixed pixels (label > 0) and z the observed values of the remaining pixels.

The grid is divided into nblocks blocks of consecutive columns, over which the sweeps of a chain are parallelised (see the keyword argument ntasks of run!). The default depends only on the number of columns, and is rarely worth changing. Each block has its own random-number stream, so results depend on nblocks, but not on the number of tasks.

HiddenMarkovRandomFields.PottsParams Type
julia
PottsParams(lattice, β, distributions)
PottsParams(lattice, β, q::Integer)

Parameter-dependent quantities for PottsLattice, computed once per parameter value: the number of labels q (always length(distributions), never inferred from the data), the table E[n+1] = exp(βn) for the possible neighbour counts n = 0,…,4, the Swendsen–Wang bond probability 1 - exp(-β), and the likelihood weights W (q×(nobs+1)): column 1 ≡ 1 (missing pixels) and W[k, o+1] = exp(ℓₖ - maxₖ ℓₖ) with ℓₖ the log-density of the oth observed value under distributions[k]. The second method is for the Potts model itself (no emission distributions).

PottsChain(lattice, rng::Xoshiro)

State of one MCMC chain on lattice: padded UInt8 labels, its own random-number generators (rng, used for initialisation and for drawing data, and one per block of the lattice for the sweeps, seeded from rng), and the number of iterations run. A new chain is initialised by initialize!, or by the first call to run!.

HiddenMarkovRandomFields.initialize! Function
julia
initialize!(chain, lattice, params)
initialize!(chains::PottsChains, lattice, params)

Cold start of chain, which resets its iteration counter: fixed pixels take their labels, observed pixels take their maximum-likelihood labels, and missing pixels are filled outward from the assigned pixels (after seeding 1% of them at random) by a breadth-first flood fill: at high temperature (β < βcrit(q)) each pixel is drawn with probability ∝ exp(β nₖ) given its assigned neighbours; at low temperature it takes the neighbour mode (random tie-break). With no observed or fixed pixels, the labels are uniformly random at high temperature, and random blocks with 5% random perturbations at low temperature.

Chains on a device (PottsChains) are initialised in the same way on the CPU, in parallel over threads, and then copied to the device.

HiddenMarkovRandomFields.run! Function
julia
run!(chain, lattice, params, niterations; sw_every = 1, ntasks = 1)
run!(chains::PottsChains, lattice, params, niterations; sw_every = 1)

Runs niterations MCMC iterations of chain (initialising it first with initialize! if needed). Each iteration is a chequerboard heat-bath Gibbs sweep, preceded by a Swendsen–Wang sweep if the chain's iteration counter is a multiple of sw_every (sw_every = 0: Gibbs only).

The sweeps are parallelised over the blocks of the lattice with ntasks tasks (see PottsLattice), which are started once per call and synchronise between the phases of each sweep. This pays off for grids of roughly 64 × 64 pixels or more. The results do not depend on ntasks. Keep the default, ntasks = 1, when several chains are already run in parallel.

The parameters may change between calls: build a new PottsParams for the same lattice, and the chain continues from its current state. This is useful, for example, between the iterations of a Monte Carlo EM algorithm (Wei and Tanner, 1990), such as the neural EM algorithm (Sainsbury-Dale et al., 2025).

The chains of a PottsChains all run together on their device, and ntasks does not apply.

HiddenMarkovRandomFields.drawZ! Function
julia
drawZ!(Zout::AbstractMatrix, chain, lattice, params)
drawZ!(Zout::AbstractArray{<:Real, 3}, chains::PottsChains, lattice, params)

Draws the missing entries of Zout (an nrow×ncol array whose observed entries are already filled) from the emission distributions given the current labels of chain, and returns Zout. The other entries are not modified.

For chains on a device (PottsChains), Zout is an nrow×ncol×nchains array on the same device. The data are drawn on the device when every emission distribution is a Normal, LogNormal, Uniform, Exponential, Gamma, Beta or Dirac distribution and Zout has a floating-point element type. Otherwise, the labels are copied to the CPU, the data are drawn there and then copied back.

GPU ​

Simulation on a GPU needs a GPU package that loads KernelAbstractions.jl, such as CUDA.jl. Pass its backend, e.g. CUDABackend(), as the keyword argument backend of simulatehiddenpotts and simulatepotts. For persistent chains, use PottsChains with the functions above. See GPU sampling.

HiddenMarkovRandomFields.PottsChains Type
julia
PottsChains(lattice, nchains::Integer, backend; rng = Random.default_rng())

State of nchains MCMC chains on lattice, held on the device of the KernelAbstractions backend, such as CUDABackend() after using CUDA. It contains the labels of every chain, scratch memory for Swendsen–Wang sweeps, and a copy of the parameter-dependent quantities of the last PottsParams used. The scratch memory is allocated at the first Swendsen–Wang sweep, and takes about 14 + 8q bytes per pixel and chain.

The chains are used like PottsChain, with initialize!, run!, getlabels! and drawZ!, but all of them are updated together. The arrays given to getlabels! and drawZ! are nrow×ncol×nchains arrays on the same device, so the data can be used there, e.g., by a neural network. Pass the same lattice object to every call. The parameters are one PottsParams for all chains, or a vector with one per chain; the chains must then share their likelihood weights, as they always do in unconditional simulation.

Random numbers come from counter-based generators (Philox2x32-10 and Philox4x32-10), seeded from rng. Results are therefore reproducible given rng, but differ from those of the CPU sampler.

This needs a GPU package that loads KernelAbstractions, such as CUDA.jl. KernelAbstractions.CPU() also works, for testing. At most 32 labels are supported, and nchains × (nrow + 2) × (ncol + 2) must be less than 2³¹.

HiddenMarkovRandomFields.βcrit Function
julia
βcrit(q)

Critical inverse temperature log(1 + √q) of the q-state Potts model on the square lattice. Realisations are disordered for β < βcrit(q) and dominated by large clusters of a single label for β > βcrit(q).
